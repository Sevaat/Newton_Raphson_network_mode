# Newton_Raphson_network_mode

Расчёт установившегося режима электрической сети методом Ньютона–Рафсона в полярных координатах.

[![Python](https://img.shields.io/badge/python-%3E%3D3.14-blue)](https://www.python.org/)
[![License: GPL v2](https://img.shields.io/badge/license-GPL--2.0-green)](LICENSE)
[![Code style: black](https://img.shields.io/badge/code%20style-black-000000.svg)](https://github.com/psf/black)

## Возможности

- Расчёт режима в полярных координатах с полной матрицей Якоби `[[H, N], [M, L]]`
- Типы узлов: `slack` (балансирующий), `pq`, `pu` (генераторный)
- Статические характеристики нагрузок (ZIP-модель) с учётом производных в якобиане
- Ветви: линии, двух- и трёхобмоточные трансформаторы; поперечные проводимости узлов и ветвей
- Демпфирование поправок, контроль сходимости по максимальному небалансу мощности
- Постобработка: мощности балансирующих узлов, потоки и потери в ветвях, суммарные потери
- Ввод/вывод в JSON, валидация данных через Pydantic

## Требования

- Python ≥ 3.14
- [Poetry](https://python-poetry.org/) ≥ 2.0
- Зависимости: `numpy`, `pydantic`

## Запуск

```bash
poetry run python main.py
```

`main.py` последовательно рассчитывает режимы из `data/test_data_1.json` и `data/test_data_2.json`.
Для своей сети положите JSON-файл в папку `data/` и вызовите `main("имя_файла.json")`.

Результаты сохраняются в `result/result_<дата-время>.json`.

## Формат входных данных

JSON-файл содержит четыре секции:

### `CALCULATION PARAMETERS`

| Поле | Описание |
|---|---|
| `accuracy` | допустимый небаланс мощности, МВт/Мвар |
| `max_iterations` | предельное число итераций |
| `damping` | коэффициент демпфирования поправок (1 — без демпфирования) |

### `LOADS` — ZIP-модели нагрузок

| Поле | Описание |
|---|---|
| `load_name` | уникальное имя нагрузки |
| `p_0`, `q_0` | номинальные мощности при напряжении `u_0`, МВт/Мвар |
| `z_p`, `i_p`, `p_p` | доли P по сопротивлению / току / мощности (сумма = 1) |
| `z_q`, `i_q`, `p_q` | доли Q по сопротивлению / току / мощности (сумма = 1) |
| `u_0` | напряжение номинального режима нагрузки, кВ |

### `NODES` — узлы сети

| Поле | Описание |
|---|---|
| `node_name` | уникальное имя узла |
| `type_node`, `type_node_current` | исходный и текущий тип узла: `slack`, `pq`, `pu` |
| `u_base` | базисное напряжение, кВ |
| `u_magnitude`, `u_angle` | модуль (кВ) и угол (град.) напряжения: задание для slack/PU, начальное приближение для PQ |
| `g_shunt`, `b_shunt` | поперечная проводимость узла, См |
| `p_gen`, `q_gen` | генерация в узле, МВт/Мвар |
| `q_min`, `q_max` | ограничения реактивной мощности генерации, Мвар |
| `loads` | список имён нагрузок из секции `LOADS` |

### `BRANCHES` — ветви сети

Секции `LINES`, `TRANSFORMERS2`, `TRANSFORMERS3` (модели — в `src/model/branch.py`).
Поля линии:

| Поле | Описание |
|---|---|
| `branch_name` | уникальное имя ветви |
| `node_1`, `node_2` | имена начального и конечного узлов |
| `r_1`, `x_1` | продольные сопротивление и реактанс, Ом |
| `g_shunt`, `b_shunt` | поперечная проводимость линии, См |

Примеры полных файлов — в [`data/`](data/).

## Результаты расчёта

Выходной JSON повторяет входные секции (с рассчитанными напряжениями) и дополняется:

- `SLACK POWERS` — P, Q генерации балансирующих узлов (нагрузка узла + отдача в сеть);
- `BRANCH FLOWS` — потоки P/Q с каждого конца ветви и потери `dp`, `dq` в ней;
- `TOTAL LOSSES` — суммарные активные и реактивные потери в сети.

## Метод расчёта

На каждой итерации вычисляются небалансы ΔP, ΔQ и решается система

```
J · [Δδ, ΔU]ᵀ = −[ΔP, ΔQ]ᵀ,   J = [[∂P/∂δ, ∂P/∂U], [∂Q/∂δ, ∂Q/∂U]]
```

Неизвестные: углы всех узлов кроме slack; модули всех узлов кроме slack и текущих PU.
Диагональные элементы N и L учитывают производные ZIP-нагрузок по напряжению.
Поправки умножаются на `damping`.

- **Сходимость:** `max(|ΔP|, |ΔQ|) ≤ accuracy`.
- **`ConvergenceError`:** вырожденный якобиан, недопустимое напряжение, лимит итераций.
- Предупреждение в лог при напряжении узла ниже 0.7 от заданного.
